# 立体围棋

立体围棋（Spatial Go）是一款使用 ARKit 与 RealityKit 构建的空间围棋项目。它不是把传统棋盘换成 3D 外观，而是把二维围棋的四方向连接推广到三维空间中的六方向连接，让玩家围住由离散空交叉点构成的“领体”。

## 当前状态

仓库目前仍是 SwiftUI 初始工程，尚未实现规则引擎或 AR 功能。产品设计和实施计划已经形成：

- [设计说明](docs/plans/2026-09-03-立体围棋-design.md)
- [实施计划](docs/plans/2026-09-03-立体围棋-implementation.md)

不要把文档中的目标能力描述成现有实现。构建通过也不能证明水平面锚定、准星选点、真机性能或完整玩法已经完成。

## 核心体验

- 从单层 `N × N × 1` 棋盘学习基础规则。
- 通过“面动成体”理解新增的上、下连接方向。
- 在已检测的桌面或地面上锚定三维棋盘。
- 使用设备中央准星瞄准交叉点，并通过身体移动产生视差。
- 双指缩放棋盘以选择密集位置；首版不旋转棋盘。
- 棋盘尺寸可配置，每维最大 19，支持 `19 × 19 × 19`。
- 首版由同一真人依照轮次操作黑白双方；电脑玩家只保留扩展接口。

## 三维规则摘要

- 每颗棋最多有左、右、前、后、上、下六个相邻点。
- 同色棋通过六方向形成棋块，气是棋块相邻的不同空点。
- 落子后先同时移除零气敌块，再检查己方是否自杀。
- 使用包含下一行棋方的情境超级劫规则。
- 连续两次停着进入死棋确认；意见不一致则恢复对局。
- 终局采用三维面积法：盘上己方棋子数加己方控制的空点数。
- 空区只接触一种颜色时归该方；接触双方或不接触棋子时为中立。
- 默认白方贴 6.5 目，以整数半目存储和计算。

完整规则以设计说明中的 `3d-go/1` 为准。规则文本已经过 7 轮独立空白审核，最终一轮结论为“无审核意见”。

## 架构

```text
SwiftUI
  ↓
GameSession
  ├── Go3DCore：棋盘、规则、计分、日志、快照
  ├── PlayerController：真人、手动对手、电脑扩展点
  └── ARBoardCoordinator
        ├── ARKit：平面检测、世界跟踪与锚点
        ├── CrosshairSelector：中央射线选择
        └── RealityKit：棋盘与棋子渲染
```

`Go3DCore` 是唯一棋局数据源，不依赖 SwiftUI、ARKit 或 RealityKit。渲染层只消费不可变快照：正常使用动作增量更新，周期性只比较 revision/digest，发现不一致后才执行数组 diff 或重建。

## 性能策略

`19³` 有 6,859 个交叉点和约 19,494 条连接线。项目仍会显示完整棋盘，但不会把每条线都实现为单独实体：

- 网格线合并为少量 Mesh。
- 棋子共享 Mesh 和材质，大棋盘按颜色和空间区块批渲染。
- 空交叉点不维护复杂碰撞体。
- 准星选择使用棋盘局部空间中的数学射线，按 20–30 Hz 更新。
- 每 2–3 秒摘要巡检只作快速信号；每 30 秒和关键生命周期事件执行紧凑数组精确核对；独立实体账本审计负责发现缺失或损坏的 RealityKit 分块。

这些是设计策略，不是已测得的性能结论。`19³` 必须在最低目标 ARKit 真机上分别验证空盘、半盘和高密度盘。

## 开发要求

- Xcode 及项目当前配置所需的 iOS SDK。
- 支持 ARKit 世界跟踪的 iPhone 或 iPad，用于最终运行验收。
- 模拟器可用于规则测试、SwiftUI 流程和构建检查，但不能验证真实 AR 行为。

开始实现前，请先阅读 [AGENTS.md](AGENTS.md) 和实施计划，并在独立分支或 worktree 中逐任务执行。

## 验证边界

交付时应分别报告：

1. 纯 Swift 规则测试。
2. Simulator 构建和非 AR 界面流程。
3. ARKit 真机锚定、准星交互和生命周期恢复。
4. 真机 Instruments 性能和热状态。
5. VoiceOver、Dynamic Type、对比度与 Reduce Motion 验收。

其中任何一层通过，都不能替代其他层。

## 路线图

1. 三维棋盘数据结构与规则状态机。
2. 日志重放、死棋确认和面积计分。
3. AR 水平面锚定与完整棋盘渲染。
4. 中央准星、缩放和手动黑白对局。
5. 数据源—渲染层同步修复与真机性能优化。
6. 在稳定规则 API 上实现电脑玩家。
7. 后续评估联机、共享锚点和自由空间棋盘。
